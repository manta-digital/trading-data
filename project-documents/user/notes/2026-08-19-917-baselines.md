The two `test_cli_lists.py` failures are the known pre-existing pair: the tests
assert on an operator-config symbol list named `priority1`, and
`config/symbol-lists.yaml` defines only `smoke` and `sp500`. They are unrelated
to this slice and are expected to keep failing after it (slice 907 owns them).

**On attribution:** three catalog races map to five disrupted tests, so at least
two are cascade effects — a fixture erroring takes dependent tests with it. Three
is the hard count of races; five is the blast radius. Do not restate five as a
race count.

### This is worse than previously recorded

The rate on record was "one per full integration run." This run produced **three
races and five disrupted tests**. Two of the five —
`test_migration_051_052` and `test_data_status_equivalence` — are on the original
rotating-flake list, which corroborates that this is the same phenomenon at a
higher rate rather than something new.

Success criterion 5 (five consecutive runs with zero races) therefore has a
firmer baseline than the design assumed.

### Incidental confirmation of the morning's host fixes

An earlier attempt at this same run, before the overcommit and `shared_buffers`
changes, died with a server-side `psycopg.errors.OutOfMemory` (`Failed on request
of size 48 in memory context "SPI Exec"`) and a client-side `MemoryError` inside
pytest. This run completed cleanly on the same machine with the same suite. That
is not proof, but it is consistent with the diagnosis.

### Finding: leftover test roles in production's catalog

Before A.1 ran, `t913_app_29b4ce5b85` and `t913_mig_29b4ce5b85` were present in
production's shared `pg_authid` — residue from an interrupted run.
`test/integration/data/test_role_privileges.py` creates a per-run pair and drops
them in its fixture teardown; a run that dies in between leaves them behind, and
nothing sweeps them.

This is live evidence for the slice's second stated cost — roles are cluster-wide,
so a test run writes into the catalog production depends on. It is the class of
residue that stops existing once the test cluster is separate.

**Dropping the stale roles is not part of this slice.** They are production
catalog objects and removing them is a Project Manager decision.
