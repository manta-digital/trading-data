# 915 Host Survey — prod `.144` (2026-08-16)

Read-only measurements for slice 915 Section 1 (tasks 1.2, 1.4, 1.6). Run
locally on the production host `manta9000` (`192.168.1.144`) by an agent with
host access. Nothing was installed or configured.

Recorded here because this session has no SSH access to `.144`; the raw output
is the evidence behind the task-file checkoffs.

## Findings that changed the task breakdown

| Finding | Consequence |
|---|---|
| `PGDATA` on `/dev/nvme0n1p2` (`/`), restore target `/data` on `/dev/nvme1n1p1` — **separate physical devices** | Shared-fate concern resolved. Archive destination (4.1) and restore drill (7.1) both land on `/data` |
| `replication` admitted **from localhost only** | `pg_basebackup` runs on `.144` itself. No `pg_hba.conf` edit needed; 141 GB never crosses the network |
| `pg_verifybackup` has **no `/usr/bin` wrapper** | Task 3.2 must call `/usr/lib/postgresql/17/bin/pg_verifybackup` explicitly, and must fail rather than skip if absent |
| `rclone` is **v1.60.1-DEV** (2022-era distro build) | Verify B2 backend and `rclone check` before Section 6 depends on them |
| **Nothing re-invokes acquisition** — no cron entry, no project timer | The backup schedule cannot assume acquisition is running at any given hour |
| `/data` measured **760 GB** free, not the ~800 GB recalled | Size Section 7 against 760 GB |

Unmeasurable in this pass: `sudo crontab -u postgres -l` (no TTY). Low risk, but
check before task 9.1 writes a schedule.
