## Close-out

- **Saturday minute peak.** The 6.2 GiB minute-pass peak appears on every Saturday firing in the window and on no other day
  (2026-09-19, 09-26, 10-03, 10-10; other days 75–144 M). Probable cause:
  the trailing phase's gap-row seeding, not investigated here.
- **Kalshi contract diff:** none. No pass code changed.
- **Realtime paths:** neither is ruled out; a `Type=simple` streaming source
  is the named reopen trigger for stagger.
- **Data-correctness contract:** no rows; the slice touches no data path.
- **The bound is declared, not in force.** Production runs `v0.19.0` without
  it until 234's cutover installs the slice file and checks `memory.max` and
  `memory.events` (issue #33).
- **Gap for 234 (runbook add-a-source step).** The re-derive step comes
  before install, but a new unit has no journal until it is installed and
  has fired, so the script exits 2 for 234's tick unit at that point. 234
  must either install the unit, fire it once, then re-derive and reinstall,
  or decide how the tick peak enters the sum before the unit exists.
