# Slice Plan: Data Acquisition

## Source

[120-arch.data-acquisition.md](120-arch.data-acquisition.md)

## Approach

Vertical slices, equities-only initially. Each slice leaves the system in a working state and delivers concrete value (foundation, end-to-end capability, or operational hardening). Sequencing follows the architecture's "daily before minute" principle: prove the resumable orchestrator pattern on the simpler daily case, then apply it to minute data. The minute pipeline is the operational pain point today, but daily is the right place to get the patterns right.

Slices 121–125 cover the equities/AlphaVantage scope. Later slices (futures, Databento, tick acquisition, flat file import) extend the system and may be re-indexed as the work is refined. The 120 band has 19 slots, which is sufficient for the anticipated scope.

External operational gate: the minute pipeline (slices 124–125) cannot deploy to production until the irreplaceable historical minute data on daily-host/minute-host is backed up. This is handled by the PM outside the slice plan. Production deployment itself is tracked as slice 126.

## Slices

1. [x] **(121) Acquisition State Schema and Orchestrator Core** — Foundation slice. Create the `acquisition_state` table on minute-host with the schema from the architecture (`(symbol, granularity, provider)` primary key, watermark/status/error/retry columns). Define the shared orchestrator interface: a fetch→validate→write→checkpoint loop that any acquisition workflow uses. Implement structured event emission scaffold (write to a simple events table or append-only file — Initiative 180 may formalize later). No provider changes, no daemon, no end-user-facing CLI changes. Verifiable via: state schema migration applied to test DB, orchestrator unit tests with fake provider/storage, CLI can read empty state via a new `mt data state` command.

2. [x] **(122) Daily Provider Interface and AlphaVantage Daily Provider** — Define `IDailyDataProvider` protocol modeled on the existing `IMinuteDataProvider`. Implement `AlphaVantageDailyProvider` (using the same httpx + rate limiter patterns as the minute provider, calling `TIME_SERIES_DAILY_ADJUSTED`). Replace `marketservice.py` with a new daily orchestrator that uses the slice 121 orchestrator core. Wire `mt data daily update SYMBOL` and `mt data daily update-all` through the new path with full state tracking and resume. Single-symbol and batch operations are resumable: a failed `update-all` at symbol N resumes at symbol N on next invocation. Verifiable via: CLI commands work end-to-end against test DB, watermarks updated correctly, integration test simulates failure and verifies resume.

3. [x] **(123) Daily Acquisition Daemon** — Wrap the daily orchestrator in a long-running daemon process. Continuous symbol cycling, graceful shutdown on SIGTERM/SIGINT, "caught up" detection (every active symbol within 2 trading days), sleep-and-poll when caught up. Add `mt data daily status` CLI command that reads acquisition state and reports daemon health, current work, and per-symbol freshness. Daemon runs unattended on minute-host against test DB and proves the daemon pattern on the easy case (low request volume, simple gap model). Verifiable via: daemon runs for an extended period without intervention, survives restart with state intact, CLI status command shows accurate state.

4. [x] **(124) Minute Provider Fixes and Orchestrator Hardening** — Fix `AlphaVantageMinuteProvider`: wire the `month=YYYY-MM` parameter into `_fetch_month()` request params (currently calculated but never sent), explicitly set `extended_hours=true`, correct the docstrings that reference CSV format when the code uses JSON. Fix `RateLimiter` to release the lock during the sleep window so concurrent symbol fetches don't serialize unnecessarily. Replace `HistoricalMinuteService` with a new minute orchestrator that uses the slice 121 orchestrator core with per-month-chunk write-and-checkpoint (fetch month → validate → write via COPY → update watermark → next month). Wire `mt data minute update SYMBOL` through the new path with resume. Handle AlphaVantage's partial-month responses (intraday cutoffs) — record the actual end of the returned data as the watermark, not the requested month boundary. Verifiable via: CLI fetches a multi-month range, integration test simulates mid-fetch failure and verifies resume at the next unfetched month, watermarks reflect actual data extent.

5. [x] **(125) Minute Acquisition Daemon** — Wrap the minute orchestrator in a daemon process. Continuous gap-filling cycle: identify symbols with missing recent data or known fillable gaps, prioritize by staleness, fetch with rate limiting and retry, write per-month-chunk with checkpointing. Concurrent symbol fetching via semaphore-bounded task pool (configurable, default conservative). Coordinate with the daily daemon's rate limit allocation: daily gets full budget until caught up, then minute gets the bulk. "Caught up" definition: every active symbol's watermark within 1 trading day of now and no fillable gaps remain — gaps older than the AlphaVantage 2-year window are logged as permanently unfillable and excluded from the work queue (not retried). Add `mt data minute status` CLI command. Verifiable via: daemon runs unattended against test DB for an extended period, survives restart, fills gaps correctly, handles provider errors and retries, CLI status accurate. **External gate:** production deployment blocked until PM confirms historical minute data backup.

6. [x] **(126) Production Deployment to minute-host (systemd, single-host)** — Absorbed into slice 128. Systemd unit templates (`deploy/systemd/mt-daily-daemon.service.tmpl`, `mt-minute-daemon.service.tmpl`), journald drop-in, and install runbook (`project-documents/user/runbooks/production-deploy.md`) all shipped as part of slice 128's EODHD-aware deployment scope. Tasks file removed — all items completed or made irrelevant by the unified daemon CLI (`mt data daemon run`). Dependencies: [121, 122, 123, 124, 125, 131]. Risk: Med. Effort: 2/5.

7. [x] **(127) EODHD Minute Provider + Adjustment Layer** — Replace AV minute with EODHD, and ship the split/dividend adjustment layer alongside as a single bundled slice. Scope: (a) `EODHDMinuteProvider` implementing `IMinuteDataProvider` with `max_days_per_request = 120`; (b) per-provider chunk-window generalisation (`_compute_chunk_ranges`); (c) configuration (`MT_EODHD_API_KEY`, `MT_MINUTE_PROVIDER` enum); (d) provider-selection seam (`build_minute_provider` helper); (e) **deletion of AlphaVantage minute path** — daily AV provider unaffected; (f) schema migrations: adjusted OHLC columns (`adj_open/high/low/close`, `k_factor`, `adjusted_at`) on minute hypertable; `splits` and `dividends` tables in daily DB; (g) `splits`/`dividends` ingestion job (per-symbol; bulk-API path noted as future optimization); (h) deterministic `k_factor(symbol, date)` computation, probe-verified to exact (0.000000% error) against EODHD's published `adjusted_close`; (i) writer populates adjusted columns immediately after raw bars; (j) `mt data quality verify-adjustment` CLI command — continuously verifies stored adjusted ≡ raw × computed k ≡ EODHD-published adjusted; (k) adjustment ADR at `120-arch-adjustment-policy.md`. EODHD chosen 2026-04-26 (22-year history, $30/mo vs Polygon's 5-year cap; real-time deferred to Databento later). Out of scope: deployment (slice 128), WebSocket, real-time tier, non-equity markets, pre-engineering for spinoffs/return-of-capital edge cases. Dependencies: [124, 125, 131]. Risk: Med (k-factor edge cases will be discovered as universe expands; verifier catches divergence). Effort: 4/5.

8. [x] **(128) EODHD Catch-up and Production Cutover** — Successor to deferred slice 126. Bring the post-127 system to a state where reliable, verifiable, gap-detected minute data flows continuously: first against the test environment (no production DB credentials available locally), then to minute-host once gating signals are clean. Scope: (a) **daily daemon owns corporate-action ingest** as part of its per-symbol cycle (`update daily OHLCV → ingest splits → ingest dividends`); the manual `mt data adjustment ingest` CLI remains for ad-hoc use but is no longer the production path. The minute writer's read of splits/dividends from the daily DB now has a real producer behind it. (b) **Coverage check** as a first-class CLI: `mt data minute coverage --symbol|--all --from --to [--json]` flags symbol-dates where stored bar count is below threshold for the session type (regular hours: ≥390, ETH: configurable). Uses a market calendar (NYSE trading days) to distinguish "no data because not a trading day" from "no data because provider gap." Motivating example: NVDA has a multi-month EODHD intraday gap around its 2024-06-10 split (probe-verified 2026-04-27); Stage A verifier passes vacuously because what is stored is internally consistent. Coverage check is the only signal that catches this class of failure. (c) **Stage B verification** (`mt data adjustment verify --cross-check-eodhd`): for the date range in scope, fetch EODHD's daily `/eod` (or bulk-EOD when wired) and assert `stored adj_close ≈ EODHD published adjusted_close` per day. Catches drift between us and EODHD's source-of-truth on data we *do* have. (d) **Universe-scale backfill machinery**: `mt data minute backfill --universe active --since DATE` (or equivalent on `update-all`) drives the 22-year fill for the active-instrument set, resumable across restarts at universe-iteration granularity (not just per-symbol). Quota guard caps daily request count to a configurable fraction of the EODHD plan limit (default 80%) to avoid surprise overage. Per-symbol-pair concurrency already exists; backfill reuses it. (e) **Backfill visibility**: `mt data minute status` extended to show universe-progress (`X / Y symbols complete, Z% of expected bars present, est. completion: D days`). (f) **Coverage-gap log**: symbols/dates flagged by the coverage check are written to a `coverage_gaps` table on the daily DB so they're queryable without re-scanning, and the operator can decide whether to retry, file a provider ticket, or accept. (g) **Production deployment** to prod-host: rescoped systemd units (reuse 126 templates: `mt-daily-daemon.service`, `mt-minute-daemon.service`), `/etc/manta-trading.env` carrying `MT_EODHD_API_KEY` + DB URLs, install runbook at `project-documents/user/runbooks/production-deploy.md`, journald log limits, gated minute-service start. (h) **AV stays dormant** — file remains on disk per slice 127, `MT_MINUTE_PROVIDER=eodhd` is the production default, no AV fallback is wired (AV's 2-year window cannot meaningfully complement EODHD). Out of scope: containerization (future), Polygon evaluation (separate slice if EODHD gap-rate proves unworkable after universe coverage scan), real-time/WebSocket tier, monitoring/alerting infrastructure, secrets-manager integration. Dependencies: [121, 122, 123, 124, 125, 127, 131]. Risk: Med-High (first real production deploy; coverage scan may surface more EODHD gaps that change scope; backfill is long-running and operator-visible). Effort: 3/5.

9. [x] **(129) Named Universes, EODHD Universe Source, and Symbol Hygiene** — Replace the AV-derived `symbol_list` with an EODHD-derived universe **defined as named, configurable subsets** (SP500, R2000, NASDAQ100, manual watchlists, etc.) so we don't blanket-fetch 22 years × ~13k symbols. Scope: (a) **Named universes** — new `universes` + `universe_members` tables; each universe carries a `history_months` value, replacing the global AV-era `HISTORY_MONTHS=24` default. SP500/R2000/NASDAQ100 seeded from EODHD index-constituents or static CSVs. (b) **Daemon scoped to universes** — `mt data minute daemon --universes sp500,r2000` (or `MT_ACTIVE_UNIVERSES`) limits the work queue to the union of named-universe members instead of all active instruments. Per-symbol fresh-init lookback uses the universe's `history_months`. (c) **EODHD as universe source** — `IUniverseProvider` seam, `EODHDUniverseProvider` first impl pulling `exchange-symbol-list/US`; `mt data symbols refresh` replaces `mt data daily symbols`. Adds ~5,000 instruments AV missed (gated to `Common Stock`/`ETF`/`Preferred Stock` types by default). (d) **Optional delisted history for survivorship-bias-free use** — `--include-delisted` pulls `?delisted=1` (54k tickers, 29k delisted common stocks); rows tagged with `delisted_date`. Provides the data slice 130 needs to filter at backtest time; this slice does not implement the as-of filter itself. (e) **On-demand backfill** — `mt data minute fetch --symbol SYM --since DATE [--until DATE]` for backtest-driven gap-filling when a strategy references a symbol we don't have full history for. (f) **Per-row `data_source` tagging** — `symbol_list.data_source` column (`eodhd`/`alphavantage`/`manual`/`unknown`); daemons skip rows whose source can't serve them, so the 1,054 retained AV-only SPAC variants stop costing EODHD 404s. (g) **Symbol normalisation** — single-source mapping for slash-separated tickers (`BC/PA → BC-PA`) + quarantine for structurally malformed entries (`NXT(EXP20091224)`, `TEST_ERROR`). Also adds `first_trade_date` column to `symbol_list` so slice 130's as-of filter has the lower-bound side. Out of scope: backtest-time as-of filtering (slice 130), strategy-side `data.minute_bars(...)` API, blanket 22-year backfill of all instruments, Polygon/Finnhub universe sources, pruning existing data tables. Dependencies: [127, 128]. Risk: Low-Med (universe expansion incremental; named-universe scoping bounds quota exposure; verifier remains the safety net). Effort: 3/5.

10. [x] **(130) Survivorship-Bias-Free Backtesting Universe** — Make slice 159's data usable at backtest time. New `data.equity_universe(as_of_date, universe=None)` API filters by `first_trade_date <= t AND (delisted_date IS NULL OR delisted_date > t)` so backtests over [t₀, t₁] see only instruments that were actually tradeable on each bar's date. For index-defined universes (SP500/R2000), honours `universe_members.added_on/removed_on` so a 2015 SP500 backtest sees the 2015 constituents, not today's. Closes the `first_trade_date NULL` gap with an EODHD fundamentals provider (`fundamentals/{TICKER}::General::IPODate`). Backtest harness opts into survivorship-bias-free mode via a flag; harness raises in test mode if a strategy reads data for a symbol that wasn't active on the bar's date. Backtest reports include a "universe construction" section showing N symbols active, M later delisted, K later index-removed. Chosen approach is "Level 2: active-universe-as-of-date" — rigorous enough for honest research without storing daily point-in-time snapshots (Level 3 explicitly out of scope, revisit only if licensing/reproducibility demands it). Note: historical index-constituency data (SP500/R2000 reconstitutions) is non-trivial and expensive to source — v1 may ship delisted-aware filter only, with current-membership fallback for index strategies. Out of scope: Level-3 daily snapshots, validating delisted prices against second sources, live-trading filtering. Dependencies: [158, 159, 161]. Risk: Med. Effort: 3/5.

11. [x] **(131) Unified Schema Migration Tracking Across Both Databases** [→ slice design](../slices/131-slice.unified-schema-migration-tracking-across-both-databases.md) — Cross-cutting infrastructure prerequisite. Brings both databases (daily-OHLCV `MarketDB` and TimescaleDB minute DB) under one Python-defined schema-migration framework, with multiple named tracks (`minute`, `daily`) each with its own `schema_migrations` tracking table. Extracts the existing minute-DB runner from `TimescaleMinuteDataDB.apply_schema_migrations()` into a track-agnostic free function. Adds `mt data migrate apply [--db {minute|daily|all}]` and `mt data migrate status [--db ...] [--json]` CLI surface. Daily DB is reconciled via no-op tracking-only migration (`002_reconcile_existing_schema`) — live data untouched. Retires orphaned on-disk SQL files (`database/migrations/*.sql`, `sql/01_setup_database.sql`) that had been a recurring source of confusion. Verifiable: both DBs report status via the unified CLI; `mt data migrate apply` is idempotent across re-runs; orphaned SQL files no longer present in tree. Dependencies: none new. Risk: Low. Effort: 2/5. **Numbered 131 (renumbered from 150 on 2026-05-02)**: this slice was authored mid-stream as a cross-cutting prerequisite for slices 126 / 127 / 128, originally took an off-band index (150) and was missing from this plan. Renumbered to the next free 120-band slot when the plan was reconciled.

## Notes

- Slices 121–125 cover equities + AlphaVantage end-to-end. After 125, the system can run unattended, resume from failures, and answer "what's the state of the data?" via CLI.
- Daemon framework extraction is intentionally deferred per the architecture document. When the tick acquisition daemon is added (Initiative 200), shared patterns from the daily and minute daemons (in modules created by slices 123 and 125) will be extracted at that time.
- Slice 126 was the original closing slice (deploy daemons to prod-host); deferred 2026-04-26 because AlphaVantage's 2-year window is unsuitable for real backtesting. Slice 127 replaces AV with EODHD AND ships the adjustment layer in one bundle (originally split as 127+129; consolidated 2026-04-26 to avoid an awkward unadjusted-only intermediate state). Slice 128 deploys to prod-host and runs catch-up. Slices 129 + 130 (added 2026-04-29) handle named universes / symbol hygiene and survivorship-bias-free backtest filtering respectively; both claim indices from the previously-reserved 129+ band. Slice 131 (unified schema migration tracking) was authored 2026-04-18 as a prerequisite for slices 126/127/128 and originally numbered 150 (off-band, no plan entry); renumbered into this plan 2026-05-02. Indices 132+ remain reserved for additional equity-side work; futures and tick acquisition live in Initiative 200 (separate band).
- Each slice leaves the system in a working state. Slices 121 and 124 are the highest-risk because they replace existing modules; they include integration tests against real (test) databases to validate behavior preservation.
